# GitHub Release 內容標準

本文件定義 VPS Sentinel 的版本列表名稱與版本內文格式。所有正式版本都必須遵守此標準。

## 列表標題

固定使用：

```text
VPS Sentinel vX.Y.Z
```

- 使用專案名稱加完整語意化版本。
- 版本前保留小寫 `v`。
- 不在列表標題加入版本主題、表情符號或分類文字。
- 正式版範例：`VPS Sentinel v0.9.8`。
- 預發布版範例：`VPS Sentinel v0.8.0-rc.6`。

## 內文順序

1. 版本主題
2. 一段使用者導向的摘要
3. 有內容的分類項目
4. 必要時加入升級提醒

空分類不得顯示。

## 分類名稱

只使用下列分類：

| 分類 | 使用範圍 |
| --- | --- |
| 新增功能 | 新功能、新指令、新整合或新介面 |
| 改善 | 既有功能、操作流程、效能或介面體驗改善 |
| 修正 | 錯誤、異常行為或顯示問題修正 |
| 安全性 | 權限、驗證、網路暴露與安全防護 |
| 可靠性 | 備份、還原、失敗復原、健康檢查與穩定性 |
| 相容性 | 作業系統、舊版升級、設定格式或裝置相容 |
| 開發品質 | 測試、CI、靜態分析與發布流程 |

## Markdown 範本

```markdown
## 版本主題

用一段簡短文字說明這個版本替使用者帶來的主要改變。

### 新增功能

- 說明新增內容。

### 改善

- 說明改善內容。

### 修正

- 說明修正內容。
```

未使用的分類直接省略。

## 撰寫原則

- 使用繁體中文與台灣常用詞彙。
- 先描述使用者可感受到的結果，再補充必要技術細節。
- 每個項目只描述一件事，並以句號結尾。
- 指令、檔名、設定鍵與程式名稱使用反引號。
- 避免「最佳化」、「大幅提升」等無法具體驗證的形容。
- 不使用 GitHub 自動產生的 `What's Changed` 作為正式發布文案。
- `CHANGELOG.md` 是唯一文案來源；GitHub Release 由發布流程擷取對應版本。
